## Request

> Upgrades all deps

User confirmed scope: full major upgrades (not minor/patch-only), including React 18→19, Vite 5→8, Tailwind 3→4, TypeScript 5→7, Blockly 10→13, framer-motion 11→12, @vitejs/plugin-react 4→6.

---

## Decision

Bump every dependency in `package.json` to its latest published version, including majors with breaking changes. This is a pure dependency/tooling refactor — no user-visible product behavior should change. Tailwind v4 requires a config migration (CSS-first `@theme`/`@config`, new PostCSS plugin package) and Blockly 10→13 may have breaking API surface for `src/blockly/customBlocks.ts`; both are handled as part of this change, not deferred.

---

## Alternatives considered

| Alternative | Why rejected |
|-------------|-------------|
| Minor/patch-only bump | User explicitly asked for full upgrade; leaves known majors (React 19, Vite 8) unaddressed indefinitely |
| Upgrade one major at a time across separate PRs | More total ceremony for a small static app with no external consumers of intermediate states; single coordinated pass is lower overhead here |

## Implementation steps

1. Run `bun outdated` to confirm the exact target versions.
2. Bump `package.json` versions for: `react`, `react-dom`, `blockly`, `framer-motion`, `@types/react`, `@types/react-dom`, `@vitejs/plugin-react`, `tailwindcss`, `typescript`, `vite`. Leave already-latest packages (`react-router-dom`, `lucide-react`, `react-aria-components`, `autoprefixer` if dropped, `lefthook`, `biome`) untouched unless `bun outdated` shows them stale too.
3. Run `bun install` to regenerate `bun.lock`.
4. Migrate Tailwind config to v4: swap `postcss.config.js` to use `@tailwindcss/postcss`, update the CSS entry file's `@tailwind` directives to `@import "tailwindcss"`, and port `tailwind.config.js`'s `theme.extend` (colors, fontFamily, keyframes, animation) to the v4 equivalent (`@theme` block or `@config` bridge — pick whichever requires the least churn while keeping identical values).
5. Run `bun run build` (`tsc -b && vite build`) and fix all resulting TypeScript and build errors from the React 19 / Blockly 13 / Vite 8 API changes, without changing product behavior.
6. Manually smoke-check in `bun run dev`: landing page renders, `/app` loads, one lesson completes with correct stars/XP, Blockly toolbox renders and generates code correctly (INV-G4 sandbox still exposes only the 5 verbs).
7. Update `.ai/agents/context.md` gotchas section only if an upgraded library's API changed in a way future agents need to know.
8. Add the decision log entry.
9. Run `bun run build` — must pass before committing.

## Implementation notes

All target versions bumped via `bun add`: react/react-dom 19.2.8, blockly 13.2.0, framer-motion 12.43.0, @types/react 19.2.18, @types/react-dom 19.2.4, @vitejs/plugin-react 6.0.5, typescript 7.0.2, vite 8.2.0, tailwindcss 4.3.3, @tailwindcss/postcss 4.3.3. Removed `autoprefixer` (built into Tailwind v4).

Deviations from the plan / fixes required for `bun run build` to pass:
- `vite.config.ts`: `manualChunks` object literal no longer type-checks under Vite 8 (rolldown-backed `RollupOptions`); rewritten as a function keyed on `node_modules/<pkg>` id substring matches, preserving the same three chunks (blockly, react-vendor, framer).
- `src/vite-env.d.ts` added — TypeScript 7 rejected the untyped side-effect `import './index.css'` in `main.tsx`; this file never existed before despite being the standard Vite template file.
- Tailwind v4 migration done via `@config` bridge (kept `tailwind.config.js` as-is) rather than a full CSS-first `@theme` rewrite, to avoid colliding with pre-existing hand-written `--color-brand-*`/`--color-app-*` custom properties in `:root` (used by React Aria, not Tailwind).

Verification performed:
- `bun run build` passes (tsc -b + vite build), zero TypeScript errors.
- Manual smoke test via Chrome DevTools MCP: landing page (`/`) renders with correct Tailwind styling and gradients; `/app` world map renders; opened Jungle Adventure → "First Steps" lesson — Blockly toolbox category and flyout render all five custom blocks (move right/left/up/down, collect item) correctly; "View Code"/"View Blocks" toggle works with no console errors at any step.
