# Plan: Fix soft 404 on unknown routes

**Slug:** `fix-soft-404`
**Date:** 2026-09-04
**Status:** done

---

## Request

> seo: fix soft-404 on unknown routes (SPA catch-all returns HTTP 200)
>
> `netlify.toml` and `public/_redirects` both rewrite `/*` → `/index.html` with `status = 200`. Any nonexistent URL (typo, stale link, removed world/lesson) serves the full app with HTTP 200 rather than a real 404. React Router's catch-all (`<Navigate to="/" />` in `src/App.tsx`) then client-redirects to `/` — but the HTTP response already claimed success. Google Search Console flags this pattern as a "soft 404," which can hurt crawl budget allocation and indexing signal quality.
>
> (Issue #78, part of #74. `public/_redirects` no longer exists — it was deleted in `.ai/decisions/log/2026-08-29-05-delete-redundant-public-redirects-file.md` — so `netlify.toml` is the only redirect file affected.)

---

## Decision

Combination of options 1 and 2 from the issue, scoped tightly to what the app actually has:

1. **Netlify edge-level fix.** The app has exactly two real route prefixes: `/` (prerendered landing page) and `/app*` (SPA shell). `netlify.toml`'s blanket `/* → /index.html status=200` catch-all is replaced with `/* → /404.html status=404`, backed by a new static `public/404.html`. Any path outside those two prefixes — typo, stale link, removed content — now gets a real HTTP 404 with a real (small, on-brand, static) 404 page, before React ever loads. Static assets (`og-image.png`, favicon, the Google verification file, etc.) are unaffected: Netlify serves an existing file directly, redirects only apply when no file matches the path.

2. **Client-side fix for the remaining soft-404 inside `/app*`.** Because `/app*` itself must stay a 200 (it's a real, working prefix), a deep path under it that doesn't match any defined route (e.g. `/app/foobar`, or a bookmarked link to a world/lesson that no longer exists) still returns 200 today, then silently bounces to `/` via `<Navigate to="/" replace />` in `src/App.tsx`'s top-level catch-all `Route`. Replace that silent redirect with a dedicated `NotFoundScreen` component that (a) tells the visitor plainly the page doesn't exist instead of teleporting them to the landing page with no explanation, (b) sets `<meta name="robots" content="noindex, follow">` for the duration it's mounted (restored on unmount) so a crawler that does reach it via a stale link doesn't index it as real content, and (c) offers one big obvious button back home. This scope stays inside `src/App.tsx`'s existing top-level `*` route — no change to the nested per-world/per-lesson "not found → redirect to the parent list" behavior in `WorldDetailRoute`/`LessonRoute`/etc., which is intentional existing UX (INV-L2) and out of scope for this issue (the issue's own "Files" list only names `src/App.tsx`'s catch-all route, not those nested routes).

This combination directly fixes the GSC-flagged pattern (truly unknown top-level URLs now 404 for real) and improves the one remaining soft-200 case (deep unknown app paths) without touching working, intentional in-app redirect behavior.

---

## Alternatives considered

| Alternative | Why rejected |
|-------------|-------------|
| Netlify fix only (option 1), leave `<Navigate to="/" />` as-is | Leaves the silent bounce-to-landing UX for stale deep links under `/app/*` unexplained — a visitor with a bookmarked, now-invalid lesson URL just lands back on the marketing page with no idea why. Cheap to also fix while the route is already being touched. |
| Client-side fix only (option 2), keep the blanket `/* → /index.html 200` | Does not address the actual GSC complaint — the raw HTTP status for a genuinely unknown top-level URL stays 200 regardless of what the client renders. This is the core of the issue; skipping it would not close #78. |
| Enumerate every world/lesson id as its own Netlify redirect rule | Wildly over-engineered for two prefixes (`/`, `/app*`) and would need updating every time a world is added — worse maintenance burden than the two-prefix rule already in place. |
| Give `/app*` a real 404 too (make deep unknown app paths return HTTP 404) | Would require Netlify to understand which `/app/*` sub-paths are valid, which means duplicating the React Router route table into `netlify.toml` — impossible to keep in sync from the edge config, and every SPA has this same "valid prefix, client decides the rest" shape. The client-side `NotFoundScreen` + `noindex` is the standard fix for this half of the problem. |

## Implementation steps

1. In `netlify.toml`, change the final `[[redirects]]` block from
   ```toml
   [[redirects]]
     from = "/*"
     to = "/index.html"
     status = 200
   ```
   to
   ```toml
   [[redirects]]
     from = "/*"
     to = "/404.html"
     status = 404
   ```
   Leave the `/app*` → `/app.html` 200 block above it untouched.

2. Create `public/404.html` as a standalone static HTML file (not run through Vite/React) — dark background matching the app (`#0A0618`), a large emoji, a short "Page not found" heading and one sentence of copy, and a plain `<a href="/">` link styled as a button back to the homepage. Include `<meta name="robots" content="noindex">` in its `<head>` (belt-and-suspenders — the HTTP 404 status already tells crawlers not to index it, but an explicit tag costs nothing). Keep it dependency-free inline CSS, matching how `public/og-image.svg` is hand-authored outside the build pipeline.

3. Add three keys to `src/i18n/translations.ts` (both the `en` and `id` blocks), e.g.:
   - `'notFound.title'`: EN `"Page Not Found"` / ID `"Halaman Tidak Ditemukan"`
   - `'notFound.message'`: EN `"This page doesn't exist — maybe it moved, or the link was mistyped."` / ID `"Halaman ini tidak ada — mungkin sudah dipindahkan, atau tautannya salah ketik."`
   - `'notFound.cta'`: EN `"Back to Home"` / ID `"Kembali ke Beranda"`

4. Create `src/screens/NotFoundScreen.tsx`:
   - Functional component, no props.
   - Uses `useLanguage()` for `t()`, `useNavigate()` (or a plain `<Link to="/">`) for the CTA.
   - Full-viewport centered layout on the app's dark background (`#0A0618`), large emoji (e.g. 🧭 or 🔍 — pick one consistent with the existing mascot/emoji vocabulary used elsewhere, avoid inventing a new visual language), `t('notFound.title')` as an `<h1>`, `t('notFound.message')` as body text, and a large button-styled link using `t('notFound.cta')` that navigates to `/`.
   - In a `useEffect`, read the current `content` of `document.querySelector('meta[name="robots"]')`, set it to `'noindex, follow'` while mounted, and restore the original value in the cleanup function.
   - No new dependency — plain `useEffect` + `document.querySelector`, consistent with how `Footer` and `LanguageUrlSync` already touch browser APIs directly without a helmet-style library.

5. In `src/App.tsx`:
   - Import `NotFoundScreen` from `./screens/NotFoundScreen`.
   - Add a small `NotFoundRoute` wrapper function next to the other `*Route` wrapper functions (following the file's existing pattern), returning `<NotFoundScreen />`.
   - Replace `<Route path="*" element={<Navigate to="/" replace />} />` with `<Route path="*" element={<NotFoundRoute />} />`.

6. Run `bunx biome ci`, `bun run type-check`, and `bun run build` — all three must pass before committing.

7. Manually sanity-check in `bun run dev`: visit `/some-typo-path` and confirm the new `NotFoundScreen` renders (dev server always serves `index.html`/SPA regardless of Netlify config, so this exercises the React-side fix only — the Netlify status-code fix can't be verified locally and is trusted to Netlify's documented `[[redirects]]` behavior, consistent with how `netlify.toml`'s existing `/app*` split is already untestable under `bun run dev`/`bun run preview` per `.ai/agents/context.md`).
