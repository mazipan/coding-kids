# 2026-08-29 — Delete `public/_redirects` rather than keep it alongside `netlify.toml`

**Context:** While implementing the landing-page prerender split (`.ai/plans/2026-08-29-feat-static-landing-page-prerender.md`), `netlify.toml` gained a new `/app*` → `/app.html` redirect ahead of its existing `/* → /index.html` catch-all, so `/app/*` routes keep serving the plain SPA shell instead of the prerendered landing markup. The repo also carried a pre-existing `public/_redirects` file (`/* /index.html 200`, added in an unrelated dependency-upgrade commit on 2026-08-01, long before any of this) that Netlify copies verbatim into `dist/_redirects` at build time.

**Decision:** Delete `public/_redirects`. Netlify does not clearly document that `netlify.toml`'s `[[redirects]]` rules are guaranteed to be evaluated *before* a `_redirects` file's rules when both exist for the same site. If the `_redirects` file's bare `/* → /index.html` catch-all is matched first, it would catch every request — including `/app/*` — before the new `/app*` → `/app.html` rule in `netlify.toml` ever gets a chance, silently serving the prerendered landing markup for every game route. Since `netlify.toml` already fully subsumes what `_redirects` did (identical SPA-fallback purpose, now split further), removing the redundant file eliminates the precedence question entirely rather than depending on undocumented cross-source ordering. `.ai/agents/context.md`'s Deployment section now says explicitly not to reintroduce a `_redirects` file, so a future change doesn't silently break the `/app*` split.

**Alternatives rejected:**
- Keep `public/_redirects` and add the `/app*` rule to it too (mirroring `netlify.toml`) — works, but leaves two files that must always be kept in sync, and doesn't remove the underlying precedence ambiguity for any *other* future redirect either file might gain.
- Do nothing and assume `netlify.toml` wins — too risky to leave unverified for a mechanism (`/app*` vs `/` content split) this deployment now depends on for correctness, not just cosmetics.

**Consequences:** `netlify.toml` is now the single, unambiguous source of truth for all redirects on this project. Any future redirect change only needs to touch one file. There is a small chance some other host or tool expected `public/_redirects` to exist, but this repo's `.ai/agents/context.md` documents Netlify as the only deployment target, and the file was never mentioned there as intentional.
