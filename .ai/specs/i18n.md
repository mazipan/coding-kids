# i18n spec

## How it works

`LanguageProvider` (`src/i18n/LanguageProvider.tsx`) wraps the entire app and provides:

```ts
const { t, language, setLanguage } = useLanguage()
```

- `t(key)` — returns the translated string for the active language
- `t(key, vars)` — substitutes `{varName}` placeholders: `t('common.completed', { n: 3, total: 6 })` → `"3/6 lessons"`
- `language` — `'en'` | `'id'`
- `setLanguage(lang)` — switches language and persists to `localStorage`

## Translation file

`src/i18n/translations.ts` — flat key/value object for each language.

```ts
const en: Translations = {
  'landing.headline': 'Where Kids Become Coders',
  'common.completed': '{n}/{total} lessons',
  // ...
}
```

Exported as `TRANSLATIONS: Record<Language, Translations>`.

## Key naming convention

```
{section}.{subsection?}.{name}
```

Examples:
- `landing.headline` — hero headline on the landing page
- `landing.features.blocks.title` — feature card title
- `game.run` — run button label
- `common.xp.reward` — reusable XP badge (`⚡ {xp} XP`)
- `world.jungle.name` — world name (used in HomeScreen + LandingScreen)
- `reward.levelup` — level-up banner in RewardModal

## Sections

| Prefix | Used in |
|--------|---------|
| `landing.*` | `LandingScreen` |
| `nav.*` | `Header`, navigation labels |
| `game.*` | `LessonScreen`, `BlocklyWorkspace` |
| `grid.*` | `GameGrid` legend |
| `reward.*` | `RewardModal` |
| `world.{id}.*` | World names, taglines, concepts |
| `common.*` | Shared labels (ages, XP, stars, tries, etc.) |

## Adding a new key

1. Add the key + English string to `en` in `src/i18n/translations.ts`
2. Add the Indonesian translation to `id` — missing keys fall back to English at runtime, but all keys should have Indonesian translations
3. Use `t('your.key')` in the component — never hardcode user-visible strings

## Language detection order

1. `localStorage.getItem('codekids_language')` — user's explicit choice
2. `navigator.language.startsWith('id')` → `'id'`, else `'en'`
3. Default: `'en'`
